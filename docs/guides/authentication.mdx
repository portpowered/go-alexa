`Client` holds service and transport settings. `Session` holds one account's credentials. Load credentials from a secret store or environment and never commit or log them.

## Use an access token

```go
client, err := alexa.NewClient(alexa.WithRegion(alexaapimodels.RegionUS))
if err != nil {
    return err
}
session, err := client.NewSession(alexa.WithBearerToken(os.Getenv("ALEXA_BEARER_TOKEN")))
if err != nil {
    return err
}
defer session.Close()
```

Pass an access token to `WithBearerToken`. The session uses it for authenticated API calls.

## Refresh a token

Create a session with `WithRefreshToken`. Pass the same device registration settings used when you linked the account to `Session.RefreshAccessToken`:

```go
refreshed, err := session.RefreshAccessToken(ctx, registrationConfig)
if err != nil {
    return err
}
// Store refreshed.AccessToken and refreshed.ExpiresInSeconds in your credential store.
if err := session.SetAccessToken(refreshed.AccessToken); err != nil {
    return err
}
```

Refresh is explicit and leaves session state unchanged until you install the returned access token. The response contains an access token and its expiry interval; it does not replace your stored refresh token.

## Link an account with a code

Call `GenerateCodePair`, show the public code to the user, and keep the private code secret. After the user approves the link, call `RegisterWithCodePair`. Treat returned tokens as credentials. Start this flow only after an explicit user action.

Browser authorization URLs are implementation-derived links managed by your application. Your application supplies authorization parameters and handles callback state and PKCE validation.

## Use cookies and CSRF

Call `Session.ExchangeRefreshTokenForCookies` explicitly, store the result, and create a session with `WithCookies`. If a request needs a CSRF value, call `Session.GetCSRFToken`; requests do not fetch missing CSRF material or exchange tokens implicitly.

`WithRegion` accepts US, EU, or JP. Methods return typed errors from `alexaapimodels`; use `errors.As` to inspect wrapped errors.

CBL registration distinguishes `CodePairPendingError`, `CodePairExpiredError`
(including `invalid_code_pair`), `CodePairDeniedError`, and
`CodePairInvalidDeviceError`. Pending means the browser approval is incomplete;
expired requires a new code pair; denied requires the user to authorize again.
Invalid device means Amazon rejected device metadata; the error does not identify
which field was invalid. `CodePairRegistrationError` and
`CodePairGenerationError` expose `StatusCode` for other HTTP failures.
Transport failures remain `NetworkError`; context cancellation and deadlines
remain detectable through `errors.Is`. Provider diagnostic bodies are omitted
from CBL error messages; opt-in private wire captures retain the full exchange.

```go
var invalidDevice *alexaapimodels.CodePairInvalidDeviceError
if errors.As(err, &invalidDevice) {
    // Review the configured device profile before starting a new login.
}
```
